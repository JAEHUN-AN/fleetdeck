# 000 · 범위와 판단 근거

## 왜 이 프로젝트인가

TXR로보틱스 로봇융합연구소(마곡) 웹시스템 개발 공고 대응. 공고의 요구 항목을 기능으로 그대로 옮긴다.

| 공고 문구 | 이 프로젝트에서의 구현 |
|-----------|------------------------|
| RCS 관제 시스템 프론트/백엔드 | `backend/` (Spring Boot RCS) + `frontend/` (React 대시보드) |
| 실시간 로봇 상태 모니터링 대시보드 | STOMP WebSocket → 2D 맵, 로봇/설비 패널 |
| MQTT, gRPC, WebSocket 실시간 처리 | MQTT(VDA5050) 수집, WebSocket 중계. gRPC는 W7 이후 선택 |
| WMS/WCS/MES 상위 시스템 연동 | 모의 WMS 주문 → 미션 변환 → 디스패치 |
| 로봇 운영 데이터 수집·처리·저장 파이프라인 | MQTT → TimescaleDB 하이퍼테이블 |
| Three.js / Canvas / SVG 시각화 | W3 SVG 2D 맵 → W6 Three.js 3D |
| AMR/AGV, RCS, ACS, WCS 개발 경험 | 시뮬레이터 + 관제 서버 전체 구조 직접 구현 |

## 회사 사업과 맞춘 두 가지 보정

1. **소터 설비도 관제 대상.** 회사 매출의 뿌리는 화물 분류 설비(휠소터, 틸트트레이, 플랩소터)다.
   AMR만 관제하지 않고 고정 설비 상태(가동/정지/알람, 처리량)를 같은 화면에 올린다.
2. **ROS2 연결 지점 하나.** 회사 AMR은 ROS2 기반. 시뮬레이터를 ROS2 노드로 바꾸고 MQTT 브리지로
   붙이는 것은 W7 이후 선택 과제로 두고, 8주 중 1주 이상 쓰지 않는다.

## 프로토콜 선택: VDA5050

AGV와 관제 시스템 사이의 MQTT 메시지 표준. 채택 이유:
- 토픽·스키마가 공개되어 있어 타입 정의를 그대로 쓸 수 있다.
- 대형 고객 현장(쿠팡 등)은 여러 벤더 로봇이 섞이므로 표준 이해가 강점이 된다.
- 회사가 공식 채택했는지는 미확인. 면접에서 "왜 VDA5050인가" 답할 준비를 한다.

## 하지 않는 것

- 실제 로봇 하드웨어 연동, SLAM, 경로 계획 알고리즘
- 인증/권한 (단일 사용자 로컬 도구로 가정)
- 멀티 테넌시, 다중 사이트
