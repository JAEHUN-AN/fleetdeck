# 020 · 제조 도메인 확장 범위 (설비 연동 · SPC/FDC · Oracle)

fleetdeck 을 **물류 AMR 관제**에서 **제조 설비 관제**까지 넓힌다.
목적은 특정 공고 대응이 아니라 **제조사 이직 트랙의 학습 + 포트폴리오**다.
계기가 된 공고(Smart Factory RMS/SPC/FDC 운영, 방산, Java/Oracle/PL-SQL/React)는
범위를 잡는 참고 자료일 뿐, 그 불릿을 따라가지 않는다.

## 선택 기준: 공고 매칭이 아니라 이식성

제조 쪽 공고를 여러 개 놓고 보면 **어디에나 나오는 것**과 **그 회사에만 있는 것**이 갈린다.
배울 것은 앞쪽이다.

| 어디에나 나온다 (배운다) | 한 회사에만 있다 (안 배운다) |
|---|---|
| OPC UA, MQTT, 표준 기반 설비 연동 | BizActor, Factova (벤더 종속 미들웨어) |
| SPC 관리도, 공정능력지수, 이상 감지 | Solace (상용 브로커 — MQTT 로 구조만 같게) |
| Oracle / PL/SQL, 대용량 시계열 튜닝 | 특정 사의 MES 패키지 화면 |
| 설비 파라미터 판본·이력 관리 | 사내 코드 체계 |

벤더 제품은 **구할 수도 없고 배워도 안 옮겨간다.** 같은 구조를 공개 표준으로 만들고,
면접에서 대응 관계를 설명하는 쪽이 낫다.

## fleetdeck 에 이미 있는 것

없는 것부터 만들지 않기 위해 먼저 적는다.

| 제조에서 요구되는 것 | fleetdeck 현황 |
|---|---|
| 설비 Agent → 수집 서버 → 응용 서버 구조 | 시뮬레이터 → Spring Integration MQTT 수집 → 적재·중계 |
| 표준 프로토콜 기반 장비 연동 | VDA5050 (state/order/instantActions) 구현 완료 |
| 실시간 설비 상태 감시 | `equipment_state_log` 하이퍼테이블 + STOMP 중계 |
| 대용량 시계열 조회 | `time_bucket` 집계 API, 초당 282건 부하 실측 |
| 메시지 유실·정합성 인식 | QoS 0 유실 0.038 % 실측, QoS 1 분리 적용 |

**없는 것은 두 가지다 — 제조 표준 프로토콜, 그리고 통계·판정 계층.**

## 단계

마감이 없는 상시 트랙이다. 주차가 아니라 단계로 끊고, 각 단계가 끝날 때마다
문서 하나와 측정값 하나를 남긴다. 중간에 멈춰도 거기까지가 자산이 되도록.

### Phase 1 — OPC UA 설비 연동 (최우선)

제조 공고에서 가장 반복되는 단어이고, **VDA5050 다음으로 붙이기 가장 싼 것**이다.
이미 "표준 스펙을 읽고 구현해 본" 경로가 리포에 있다.

- 시뮬레이터에 OPC UA 서버 노드 추가 (`asyncua`) — 소터를 OPC UA 장비로도 노출
- 백엔드에 OPC UA 클라이언트 수집기 (Eclipse Milo) — 구독(Subscription) 방식
- 기존 MQTT 경로와 **같은 적재 테이블로 합류**시킨다. 프로토콜은 어댑터 계층에서 끝난다
- 측정: 구독 방식 vs 폴링 방식의 지연·부하 비교, 연결 단절 후 재구독 복구 시간

남길 문서: `docs/021-opcua.md`

> **선택 — SECS/GEM.** 반도체·디스플레이 fab 을 목표로 한다면 여기서 갈린다.
> RMS/FDC/SPC 라는 용어 자체가 fab IT 의 3종 세트고, 그 바닥 장비 표준은 OPC UA 가
> 아니라 SECS/GEM(SEMI E5/E30)이다. **일반 제조·자동차·2차전지면 OPC UA 로 충분하고,
> fab 을 노린다면 Phase 1 뒤에 SECS/GEM 파서를 하나 더 붙인다.** 지금은 OPC UA 먼저.

### Phase 2 — FDC 이상 감지

현재 설비 payload 는 `status`, `throughput_per_min` 뿐이라 이산값이다. 통계를 걸 수 없다.
**연속 센서 채널이 먼저다.**

- 시뮬레이터: 소터당 3채널 — 모터 전류(A), 벨트 진동 RMS, 베어링 온도(℃)
- 이상 주입 4종 — 드리프트 / 스파이크 / 계단 변화 / 분산 증가
  - 주입 시각·채널·유형을 **정답 라벨로 남긴다.** 이게 없으면 탐지율을 못 잰다
- 탐지기 3종 비교
  1. 정적 임계 (현행 기준선)
  2. 이동 윈도우 3σ / MAD — 스파이크에 강함
  3. EWMA — 드리프트에 강함
- 알람 억제: 연속 위반 k회 이상일 때만 경보 승격 (chattering 방지)
- 측정: 탐지율 / 오경보율 / 탐지 지연(초) — 탐지기 × 이상유형 교차표

남길 문서: `docs/022-fdc-detection.md`

### Phase 3 — SPC 통계적 공정 관리

- X̄-R 관리도 (부분군 n=5). **관리한계는 안정 구간 데이터에서 산출** — 규격한계와 혼동하지 않는다
  (이 구분을 못 하면 현업에서 바로 드러난다)
- Cp / Cpk 공정능력지수
- Nelson 규칙 중 1·2·5·6 (한계 밖 1점 / 연속 9점 편측 / 3점 중 2점 2σ 밖 / 5점 중 4점 1σ 밖)
- 대시보드에 관리도 패널 1개 (기존 시계열 차트 재사용)

남길 문서: `docs/023-spc.md`

### Phase 4 — Oracle 튜닝 · PL/SQL

제조 SI 는 Oracle 이 지배적이고, 자격요건의 "대용량 조회 성능 최적화(SQL 튜닝)"는
거의 모든 공고에 나온다. **지원자 대부분이 "해봤습니다"로만 답하는 항목이라 수치가 있으면 갈린다.**

fleetdeck 본체를 Oracle 로 이식하지 않는다 — 얻는 것 없이 2주가 날아간다.
`bench/oracle/` 에 실험 하네스만 따로 둔다.

- Oracle Free 23ai (docker), 센서 이력 1천만 건 생성
- 대상 쿼리 3종 — ①기간+설비 범위 조회 ②설비별 최신 N건 ③일별 집계
- before: 단일 테이블 / after: 일 단위 레인지 파티션 + 로컬 인덱스, 필요 시 힌트
- 측정: 실행계획(AUTOTRACE), consistent gets, p95 응답시간
- PL/SQL 패키지로 집계 배치 하나 — 커서·벌크 바인드·예외 처리를 실제로 써 본다

남길 문서: `docs/024-oracle-tuning.md`

### Phase 5 — 레시피 판본과 오적용 차단 (RMS)

**[[clausegraph]] 의 "약관 시점 축" 설계를 그대로 재사용한다.**
약관 판본 = 레시피 판본, 가입 시점 약관 적용 = 생산 시점 승인 판본 적용. 논리가 같다.

- `recipe` (설비 파라미터 세트) / `recipe_revision` (판본, 승인 상태, 유효 구간)
- 설비 보고 적용값 vs 해당 시점 승인 판본 대사 → 불일치 시 차단 경보
- 측정: 오적용 시나리오 차단율

### Phase 6 — 상위 시스템 전송 상태·정합성

MES/QIS/ERP 연계 운영 업무의 실체가 여기다.

- 송신 큐 + 상태(`PENDING/SENT/ACKED/FAILED`) + 지수 백오프 재전송
- 기간 대사 배치: 송신 건수 vs 수신 확인 건수 차이 리포트
- 이미 측정해 둔 QoS 0 유실 0.038 % 와 연결한다 — **"유실될 수 있음을 알고 만든 큐"** 라는 근거

## 도메인은 바꾸지 않는다 (판단)

**소터를 웨이퍼 장비로 위장하지 않는다.** 흉내 낸 도메인은 현업 면접관에게 한 문장이면
들통나고, 그 순간 부하테스트 수치 같은 진짜 자산까지 신뢰를 잃는다.

SPC·FDC·OPC UA 는 원래 설비 중립적이다. 소터 모터 전류에 거는 EWMA 와 식각 장비 챔버
압력에 거는 EWMA 는 같은 계산이다. 할 말은 "반도체를 해봤다"가 아니라
**"관리도·이상감지·판본 관리의 구조는 설비 종류와 무관하다. 붙이는 대상만 다르다"** 이고,
그건 사실이라 방어가 된다.

## 하지 않는 것

- 반도체 공정 도메인 모사 (위 판단)
- 머신러닝 기반 이상 탐지 — 통계로 기준선을 먼저 세운다. 라벨이 적어 ML 은 과적합만 보여준다
- 벤더 제품 모사 (BizActor / Factova / Solace)
- AMR 쪽 신규 기능 — A* 경로계획·교통제어는 기존 로드맵에 남겨 둔다
- 인증·권한 (기존 범위와 동일)

## 리스크

- **범위 확산.** 6단계는 한 번에 갈 분량이 아니다. **단계마다 문서 하나를 남기고 멈출 수 있게** 끊었다
- **도메인 거리.** 물류 소터 ↔ 제조 설비. 정면으로 인정하고 구조 동일성으로 답한다
- **Oracle 이미지 라이선스.** 개인 학습·개발은 무료지만 문구를 확인하고 시작한다
- **우선순위 경합.** clausegraph 면접 통보가 오면 그쪽이 먼저다. 이 트랙은 마감이 없다

범위·판단 근거의 원본 형식은 [docs/000-scope.md](000-scope.md) 를 따른다.
